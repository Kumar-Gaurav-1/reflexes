## 2024-10-25 - AR Tracking requestAnimationFrame Loop Optimization
**Learning:** High-frequency `requestAnimationFrame` loops (like those processing 1D canvas image data for AR tracking) are extremely sensitive to micro-stutters caused by Garbage Collection from object creation and array iteration methods (e.g. `.forEach`). Furthermore, when iterating over 1D arrays representing 2D space, iterating `y` first instead of `x` aligns with the row-major memory layout of the array, which drastically improves CPU cache hit rates. Lastly, conditional branching inside nested loops for boundary checking is an expensive operation that can be optimized by pre-calculating boundaries using `Math.max`/`Math.min` outside the loop.
**Action:** When optimizing hot loops in `requestAnimationFrame` or pixel processing, unroll loops and use direct static array lookups/assignments instead of `.forEach`. When dealing with 2D array representation in 1D memory, always iterate the row (`y`) in the outer loop and the column (`x`) in the inner loop to respect row-major layout, and hoist row-invariant calculations (like `y * width`) out of the inner loop. Pre-calculate clamped loop boundaries outside nested loops to avoid per-pixel conditional checks.
