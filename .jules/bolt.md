## 2024-10-27 - Optimizing 1D Array Access for 2D Image Data
**Learning:** In high-frequency render loops (e.g. `requestAnimationFrame` for AR hand tracking), iterating over image data using column-major order (x first, then y) causes CPU cache misses because the underlying 1D array is stored in row-major order. Additionally, evaluating conditional boundary checks (`x < 0 || y < 0`) per-pixel within nested loops adds unnecessary branching overhead.
**Action:** When iterating over canvas image data, always iterate `y` (rows) in the outer loop and `x` (columns) in the inner loop. Pre-compute and clamp boundary conditions (e.g., using `Math.max` and `Math.min`) outside the loops, and hoist row-invariant calculations (like `y * width`) to the outer loop to minimize inner loop operations.
