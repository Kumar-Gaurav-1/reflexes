## 2024-05-14 - Optimize Cache Locality in Kinetic Canvas Loop
**Learning:** In high-frequency 2D pixel processing loops (e.g., iterating over ImageData inside `requestAnimationFrame`), iterating `y` (rows) as the outer loop and `x` (columns) as the inner loop ensures row-major, contiguous memory access. In contrast, an `x` then `y` loop pattern creates large memory jumps, causing cache misses and GC micro-stutters. Also, pre-calculating and clamping loop boundaries with `Math.max` and `Math.min` outside the nested loop avoids expensive per-pixel conditional branch evaluations (e.g., `if (x < 0 || x >= width)`).
**Action:** Always structure 2D array processing loops with `y` as the outer loop and `x` as the inner loop for optimal cache locality. Always hoist boundary clamping outside nested loops in high-frequency rendering contexts.
