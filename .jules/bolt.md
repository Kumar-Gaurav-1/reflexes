## 2025-02-18 - Nested Loop Optimization in requestAnimationFrame
**Learning:** In high-frequency 2D pixel processing loops (like `requestAnimationFrame` running 60fps), iterating with `x` as the outer loop and `y` as the inner loop causes poor cache locality because memory is laid out in a row-major order (contiguous memory corresponds to row elements). Additionally, placing bounds checks (`if (x < 0 || x >= 160 || y < 0 || y >= 120) continue`) inside the innermost loop causes expensive per-pixel conditional branch evaluations.
**Action:** Always structure nested loops with `y` (rows) as the outer loop and `x` (columns) as the inner loop to ensure contiguous memory access. Pre-calculate and clamp loop boundaries outside the nested loops using `Math.max` and `Math.min` to avoid inner-loop conditionals.
