## 2024-05-24 - Avoid Garbage Collection micro-stutters and Expensive Per-Pixel Evaluation in requestAnimationFrame
**Learning:** For high-frequency `requestAnimationFrame` loops (e.g., AR tracking or canvas rendering), allocating new objects/arrays (e.g., `const cornerSamples = [...]`) and using array iteration methods like `.forEach()` cause Garbage Collection micro-stutters. Also, conditionally clamping boundaries (e.g., `if (x < 0 || x >= 160 || y < 0 || y >= 120) continue`) inside nested per-pixel loops is expensive and should be pre-calculated using `Math.max` and `Math.min`.
**Action:** Unroll static arrays and use direct variable assignments instead. Pre-calculate and clamp loop boundaries outside nested loops to avoid expensive per-pixel conditional branch evaluations.
