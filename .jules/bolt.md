## 2025-02-27 - [AR Canvas Rendering Optimization]
**Learning:** High-frequency `requestAnimationFrame` loops processing canvas pixel data are extremely sensitive to Garbage Collection (GC) overhead and CPU cache locality. Specifically, allocating array objects (like `cornerSamples = [...]`) and iterating with `.forEach` inside the loop causes significant micro-stutters. Moreover, when processing 1D arrays representing 2D image data, iterating column-first (`x` outer loop) causes cache misses, slowing down execution speed.
**Action:** Unroll static arrays into direct variable assignments to completely avoid GC allocations inside rendering paths. Structure nested pixel processing loops with `y` (rows) as the outer loop and `x` (columns) as the inner loop to ensure contiguous, row-major memory access. Pre-calculate and clamp bounds outside the nested loop using `Math.max` and `Math.min` instead of running conditional bounds checks (`if (x < 0 || ...)`) on every pixel iteration.
