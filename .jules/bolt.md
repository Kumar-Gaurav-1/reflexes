## 2024-10-10 - requestAnimationFrame Loop Optimization
**Learning:** High-frequency rendering loops, like `requestAnimationFrame`, are highly susceptible to Garbage Collection (GC) micro-stutters when allocating inline arrays or creating function closures on every frame (e.g., using `[].forEach`). Additionally, performing bounds checking inside nested pixel-scanning loops introduces thousands of unnecessary branch evaluations per frame.
**Action:** When writing or optimizing `requestAnimationFrame` hooks, avoid array allocation and iteration methods (`.forEach`, `.map`) in favor of unrolled static checks or standard `for` loops. Pre-calculate and clamp nested loop boundaries using `Math.max` and `Math.min` outside the loop to eliminate expensive per-pixel conditional evaluations.
