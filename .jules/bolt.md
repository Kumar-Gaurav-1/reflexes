## 2024-05-24 - Prevent GC micro-stutters in AR tracking loop
**Learning:** High-frequency `requestAnimationFrame` loops (like those used for AR tracking or canvas rendering) are highly sensitive to Garbage Collection (GC) micro-stutters. Allocating new objects or arrays, and using array iteration methods like `.forEach()` that create closures inside the loop, cause frequent GC pauses that disrupt the frame rate and tracking accuracy. Additionally, per-pixel conditional boundary checks in nested loops add unnecessary CPU overhead.
**Action:** When optimizing `requestAnimationFrame` loops, unroll static arrays directly into variables or pre-calculate them. Replace `.forEach()` and other array iteration methods with traditional `for` loops to prevent closure allocations. Pre-calculate and clamp nested loop boundaries (e.g., using `Math.max` and `Math.min`) outside the loop to avoid expensive per-iteration conditional branch evaluations.
