## 2023-10-28 - AR Canvas Loop Optimizations
**Learning:** In high-frequency `requestAnimationFrame` loops (like the AR tracking logic in `src/components/ar-drill-view.tsx`), even small object allocations like array `.forEach` calls (e.g., `cornerSamples.forEach`) cause GC micro-stutters. Furthermore, nested loops processing 1D canvas image data arrays representing 2D space are severely unoptimized if they iterate `x` first and recompute bounds or multiplications inside the inner loop.
**Action:** Unroll static arrays to avoid GC allocations in tight loops. Optimize 2D canvas loops by iterating `y` (rows) first, then `x` (columns) to match row-major memory layout, improving CPU cache hit rates. Clamp loop boundaries (e.g., `Math.max(0, canvasY - searchRadius)`) outside the nested loops, and hoist row-invariant calculations (like `y * 160`) out of the inner loop to minimize computation per pixel.
