## 2024-08-08 - [Optimize requestAnimationFrame Canvas Processing Loops]
**Learning:** Inside high-frequency `requestAnimationFrame` loops (e.g., AR tracking or canvas pixel analysis), allocating new objects/arrays (like `[{x: 5, y: 5}, ...]`) and using array iteration methods (like `.forEach()`) incurs unnecessary Garbage Collection overhead that can cause micro-stutters. Additionally, when processing 1D arrays representing 2D image data, traversing pixels in row-major order (`y` outer loop, `x` inner loop) and clamping loop bounds outside the loop improves cache locality and eliminates repetitive conditional checks on every frame iteration.
**Action:** When writing high-performance pixel processing routines for canvas, unroll static arrays/objects into direct variable assignments or static pre-calculated offsets to avoid allocating memory per-frame. Ensure nested iteration over pixel arrays prioritizes row-major memory layout (outer row, inner column) for cache locality, and extract bounds logic (`Math.min` / `Math.max`) outside the loop.
