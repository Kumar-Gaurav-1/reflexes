## 2025-05-18 - Optimize requestAnimationFrame loops for zero GC and maximum cache hits
**Learning:** High-frequency `requestAnimationFrame` loops in this codebase (like `detectMotion` inside `src/components/ar-drill-view.tsx`) iterate over large 1D pixel arrays derived from a 2D canvas. When mapping a 2D space `(x,y)` onto a 1D pixel array `(x + y * width)`, reading pixels in column-major order (outer loop `x`, inner loop `y`) causes terrible CPU cache misses. Furthermore, declaring array objects (e.g. `const cornerSamples = [...]`) or calling array iteration functions (`forEach`) inside the function creates micro-allocations every frame, eventually triggering Garbage Collection pauses (stutters).
**Action:** When optimizing tight frame-loops, swap nested loops to be row-major (outer loop `y`, inner loop `x`) to exploit spatial locality in memory. Hoist calculations like `y * width` out of the inner `x` loop. Avoid creating arrays or objects inside `requestAnimationFrame`, instead explicitly unroll them or move their declarations outside of the function closure. Pre-calculate boundaries (`Math.max`, `Math.min`) to minimize conditional logic inside nested loops.
