## 2023-10-27 - [AR Loop Object Allocation & Inner-Loop Branching]
**Learning:** The `detectMotion` function in `ar-drill-view.tsx` was allocating a new array of objects (`cornerSamples`) on every single `requestAnimationFrame` tick, causing continuous garbage collection pressure. Additionally, the nested pixel-scanning loops performed dynamic bounds checking (`if (x < 0 || x >= 160 || y < 0 || y >= 120) continue`) on every single iteration (up to 256 times per target per frame), creating unnecessary branch mispredictions and slowing down the kinetic detection loop.
**Action:** Always extract static coordinates into module-level typed arrays (`Int32Array`) and pre-calculate linear buffer offsets when possible. For nested spatial loops, clamp iteration boundaries (using `Math.max`/`Math.min`) *before* entering the loops to guarantee safe execution without inner-loop bounds checks.
