## 2024-09-04 - Optimize AR Kinetic Tracking Loop
**Learning:** In a high-frequency `requestAnimationFrame` loop performing pixel manipulation (like AR tracking), dynamic object allocation, inner-loop bounds checking (`if (x < 0 || x >= 160 || y < 0 || y >= 120) continue`), and non-contiguous memory access (looping `y` inside `x` for 1D typed arrays representing 2D image data) can cause measurable GC micro-stutters and CPU cache misses.
**Action:** Always move static data (like sampling coordinates) outside the render loop or unroll it. Pre-calculate loop boundaries with `Math.max` and `Math.min` before entering nested loops to avoid branch evaluation on every pixel iteration. Ensure inner loops iterate over contiguous memory (e.g., `x` is the inner loop, `y` is the outer loop for row-major image data).
