## 2024-05-18 - AR requestAnimationFrame Loop Optimization
**Learning:** High-frequency rendering loops (like AR hit detection processing 60 times a second) are highly sensitive to Garbage Collection micro-stutters and per-pixel conditional branching. In `ar-drill-view.tsx`, allocating an array of objects `[{x: 5, y: 5}, ...]` and using `.forEach()` inside `detectMotion` caused unnecessary memory pressure and frame drops. Furthermore, evaluating boundary checks `if (x < 0 || x >= 160 || y < 0 || y >= 120) continue` for every single pixel in a search radius added significant computational overhead.
**Action:** Unroll static arrays and loops into direct variable assignments within `requestAnimationFrame` loops. For nested search/mapping loops, pre-calculate and clamp loop bounds using `Math.max` and `Math.min` before the loop starts to avoid expensive branch evaluations per iteration.
