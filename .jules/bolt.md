## 2024-05-15 - Optimize requestAnimationFrame loops and Image Processing Cache Locality
**Learning:** In high-frequency `requestAnimationFrame` loops (e.g., pixel processing), allocating new arrays (like `cornerSamples = [...]`) and using array iteration methods like `.forEach()` cause Garbage Collection micro-stutters. Furthermore, nested loops iterating over image data should be ordered with `y` (rows) outside and `x` (columns) inside to ensure contiguous, row-major memory access for cache locality. Also, pre-calculating and clamping loop boundaries (e.g., `Math.max` and `Math.min`) outside the nested loops avoids expensive per-pixel conditional evaluations.
**Action:** Unroll static arrays and use direct variable assignments instead of array iteration in high-frequency loops. Structure nested image processing loops with `y` as the outer loop and `x` as the inner loop. Pre-calculate clamped boundaries before the loop.
